RESOURCE CONTENTION ANALYSIS
======================================================================

Serial bo_loop:   94.4s
Parallel bo_loop: 19.5s (8 processes)
Speedup:          4.85x

✅ PARALLELISM IS HELPFUL - 8 processes gives 4.85x speedup on BO loop

No significant resource contention detected. The fork context allows
child processes to share the compiled PyTensor graph via copy-on-write,
so zarr I/O is read from memory (not disk) in all processes.

TOP TIME-CONSUMING FUNCTIONS (from cProfile, serial run)
======================================================================

1. xarray/zarr I/O:          ~125s (stack operations on posterior data)
2. response_mu evaluation:    ~86s (PyTensor graph evaluation)
3. set_posterior:             ~80s (numpy array operations)
4. zarr indexing init:        ~19s (coordinate indexing)
5. asyncio event loop:        ~17s (subprocess coordination)

These are all in the evaluate_allocation() path (13 calls in serial,
12 calls in parallel due to early termination).

OPTIMAL PROCESS COUNT
======================================================================

8 processes is near-optimal for this workload:
- BO loop speedup: 4.85x (serial vs 8 procs)
- No zarr I/O contention (pooled posterior is in-memory)
- No PyTensor graph compilation overhead (fork context shares graph)
- Each worker compiles its own CarryInBudgetOptimizer once

RECOMMENDATIONS
======================================================================

1. Keep n_processes=8 for full BO runs (100 evaluations)
2. v_q1_baseline (65.6s) is the biggest single bottleneck - consider
   caching with xarray/zarr or reducing n_draws
3. BO loop (94.4s serial → 19.5s parallel) scales well with processes
4. winner_eval (6.7s) is fast and doesn't benefit from parallelism
5. Baseline allocation caching saves ~30s per run (Q1 + Q2)
6. Consider pre-compiling the CarryInBudgetOptimizer to save ~1s

SCALING TO 100 EVALUATIONS (ESTIMATED)
======================================================================

With 100 evaluations, 3 outcomes each, 8 processes:
- BO loop: ~100 * 3 / 8 * 19.5/15 ≈ 487s (8 min)
- Plus overhead: ~30s
- Total estimate: ~520s (8.7 min)

With 100 evaluations, 3 outcomes each, 1 process:
- BO loop: ~100 * 3 * 94.4/15 ≈ 1888s (31 min)
- Total estimate: ~2055s (34 min)

Parallel gives 4x speedup for full run.
